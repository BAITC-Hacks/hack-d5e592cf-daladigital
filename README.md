# AI Протоколист · Самрук-Қазына

Локальный прототип автопротоколирования совещаний: три входа звука → распознавание русской, казахской и смешанной речи → различение голосов → извлечение решений и поручений → проверка секретарём → PDF/DOCX и контроль сроков.

> Это **ассистент с обязательной проверкой человеком**, а не система автоматического утверждения решений. Демонстрационный прототип не является готовым промышленным решением для реальных конфиденциальных заседаний АО «Самрук-Қазына».

## Быстрый запуск

Нужны Python 3.11–3.12, `ffmpeg` / `ffprobe`, Chrome (для записи вкладки), запущенная Ollama и свободное место под Python-зависимости, модели и записи (рекомендуется от 8 ГБ). На Linux потребуется установленный Unicode-шрифт для PDF. Все команды выполняются из корня репозитория.

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

Откройте `http://127.0.0.1:8000`. Установку выполняют один раз; для следующих запусков достаточно `bash scripts/start.sh`. Если Ollama ещё не запущена, откройте её приложение или выполните `ollama serve` в отдельном терминале. Скрипт установки выбирает Python 3.12 / 3.11; при необходимости задайте `PROTOCOL_PYTHON=/path/to/python3.12`.

Модели загружаются **только при подготовке**. Для работы без сети предварительно выполните подготовку на разрешённой машине и перенесите каталог моделей в `PROTOCOL_MODEL_DIR`; Ollama-модель тоже должна быть установлена локально. Python-среду устанавливайте на целевой машине: копирование готовой среды между ОС не поддерживается. После подготовки конвейер не вызывает внешние AI API. Сервер запускается на `127.0.0.1`; в прототипе нет аутентификации.

`/api/health` показывает состояние компонентов и локальных весов. Он не гарантирует качество распознавания; его подтверждает пробный прогон.

## Хранение и восстановление моделей

Данные приложения отделены от исходного кода. Каталог приложения по умолчанию:

- macOS: `~/Library/Application Support/AI-Protokolist`;
- Linux: `~/.local/share/ai-protokolist` (или `$XDG_DATA_HOME/ai-protokolist`, если переменная задана);
- собственное размещение: переменная `PROTOCOL_HOME` с абсолютным локальным путём.

Внутри находятся `runtime/` (Python-среда), `models/` (веса распознавания и голосов) и `data/` (SQLite, записи, результаты). Каталоги данных и моделей можно отдельно задать через `PROTOCOL_DATA_DIR` и `PROTOCOL_MODEL_DIR`. Веса Ollama остаются в её собственном хранилище. Переменные должны быть одинаковыми при установке и запуске.

Если совещания уже были созданы в прежнем `.data`, после установки среды **при остановленном сервере** перенесите их командой из корня репозитория:

```bash
# macOS; на Linux используйте runtime/bin/python из своего PROTOCOL_HOME
"$HOME/Library/Application Support/AI-Protokolist/runtime/bin/python" -m app.migrate_data /absolute/old/.data
```

Целевой каталог `PROTOCOL_DATA_DIR` (по умолчанию `PROTOCOL_HOME/data`) должен быть пустым. Миграция копирует записи и базу в новое хранилище; оригинальный каталог сохраняется. После успешного переноса запустите приложение через `bash scripts/start.sh`. Укажите настоящий абсолютный путь к старому `.data`; пути в примере заменяются на ваши.

Если после первого переноса в старом приложении появились новые совещания, повторите команду с `--merge`: `python -m app.migrate_data /absolute/old/.data --merge` (используйте Python из среды приложения). Этот режим добавляет только отсутствующие ID совещаний, их исходные записи и журнал изменений. Существующие совещания в новом хранилище сохраняются без перезаписи; события аудита получают новые ID. Исходный архив также сохраняется.

Ошибка `File model.bin is incomplete: failed to read a value of size 4 at position 0` означает, что локальный файл весов не читается как полная модель. Причиной может быть оборванная загрузка или выгруженный macOS/iCloud файл в синхронизируемой папке `Documents`. Поэтому рабочая среда и модели больше не создаются в `.venv` / `.data/models` рядом с репозиторием. Не помещайте `PROTOCOL_HOME` в синхронизируемую папку.

Для восстановления остановите сервер, выполните `bash scripts/setup.sh` с доступом к сети, затем `bash scripts/start.sh`. В карточке ошибочного совещания нажмите **«Повторить обработку»**: исходная запись сохраняется, повторная загрузка аудио не нужна. **«Обновить AI-анализ»** пересчитывает содержание уже готового транскрипта и не заменяет повторное распознавание при ошибке `model.bin`.

## Три входа

| Режим | Как работает | Проверка |
|---|---|---|
| Переговорная | Chrome получает звук микрофона, `MediaRecorder` сохраняет аудио в локальное хранилище | Индикатор уровня должен реагировать на речь до начала записи |
| Готовая запись | Загрузите MP3, WAV, M4A, MP4, WebM или OGG до 500 МБ | Видеодорожка MP4 отбрасывается локальным `ffmpeg` |
| Meet / Zoom / Teams | Приложение открывает ссылку в отдельной вкладке; человек входит под именем «AI Протоколист», организатор допускает его; пользователь возвращается к приложению и выбирает вкладку со звуком через системный диалог Chrome | «Звук поступает» появляется только при ненулевом аудиосигнале |

Для онлайн-встреч это **сопровождаемое подключение**, а не автономный бот. Приложение не использует Meet Media API, Zoom RTMS или Teams media bot API и не обходит политику организации. В Chrome нужно выбрать **вкладку** встречи и включить «Передавать звук вкладки». Захват требует разрешения пользователя и `localhost` либо HTTPS. Выбор окна или всего экрана не гарантирует аудио; если аудиодорожки нет, запись не запускается. Захват вкладки не добавляет звук микрофона этого же компьютера: собственные реплики нужно учитывать отдельно, например записывать встречу с устройства отдельного участника. Видео не передаётся в `MediaRecorder` и не сохраняется; браузер может временно показывать видеопревью системного диалога. Если платформа не разрешает браузерный/гостевой вход, используйте файл записи, полученный разрешённым способом. Ссылка проверяется на HTTPS и домен платформы; сервер на неё не обращается.

При потере потока запись завершается. Продолжительная тишина (>10 секунд) сохраняется в карточке как интервал для ручной проверки. Тишина не доказывает технический сбой: это индикатор, а не диагноз.

## Проверка и выходы

1. Система создаёт черновик с репликами, временем и ID источников.
2. Локальная модель относит реплики к поручениям (`action`), решениям (`decision`), стратегическим инициативам (`initiative`), открытым вопросам (`question`) и рискам (`risk`). Неопределённое «развить отрасль» не считается автоматически исполнимым поручением.
3. Секретарь сверяет аудио, подтверждает имена говорящих, редактирует/добавляет элементы, уточняет сроки и утверждает протокол. Обращение «Гульмира, вам слово» помогает предложить имя следующего говорящего, но до подтверждения это предположение. Само упоминание имени не доказывает личность говорящего. Неуказанный исполнитель или срок остаётся пустым, а не угадывается.
4. Готовый протокол можно скачать в PDF/DOCX до утверждения: файл помечается как черновик. По умолчанию сначала идёт полный фактический текст совещания по тематическим разделам, а в конце — отдельное **«Саммари по ключевым пунктам»** с краткими итогами тем, решениями и поручениями. Доступна и компактная версия без реплик участников. После проверки секретарём скачивается утверждённый протокол, его поручения попадают в дашборд сроков; статус исполнения можно менять после утверждения.

В API полный протокол скачивается по `/api/meetings/{id}/export?format=pdf` (или `format=docx`); `include_transcript=true` включён по умолчанию. Для компактной версии с итогами и поручениями добавьте `&include_transcript=false`. Требуются готовые саммари и реплики. При ручном редактировании саммари прежние автоматически выделенные тематические разделы сбрасываются, чтобы экспорт содержал актуальный текст. Уже сохранённые совещания получают тематическую структуру после обновления AI-анализа.

Сохраняются исходная запись, нормализованный WAV, JSON-данные в SQLite и журнал изменений. Корень — `data/` в каталоге приложения (можно изменить `PROTOCOL_DATA_DIR`). Не коммитьте данные или исходные записи.

## Архитектура

```text
Файл ────────────────┐
Микрофон ────────────┼→ локальная запись → ffmpeg → faster-whisper → diarize (Silero + WeSpeaker)
Вкладка встречи ─────┘                                  ↓
                                     реплики с временем и говорящим
                                                     ↓
                                    Ollama / Qwen3 → проверка секретарём
                                                     ↓
                                     SQLite → PDF/DOCX + дашборд
```

Сервер: FastAPI; очередь: один локальный worker (чтобы не запускать несколько тяжёлых моделей одновременно); хранилище: SQLite; браузер: статический HTML/CSS/JS без внешних библиотек/CDN. Весь UI работает через HTTP API (`/api/docs`); для файлов есть CLI:

```bash
# macOS; на Linux путь начинается с ~/.local/share/ai-protokolist
"$HOME/Library/Application Support/AI-Protokolist/runtime/bin/python" -m app.cli '/path/to/meeting.mp3' --title 'Комитет по развитию' --date 2026-09-23 --participants 'Председатель, Гульмира'
```

CLI возвращает ID, саммари и элементы JSON; полный протокол остаётся в локальном хранилище и виден в интерфейсе. Дата важна для интерпретации относительных сроков («завтра», «через неделю»).

## Воспроизводимая проверка

```bash
# macOS; используйте runtime/bin/python из своего PROTOCOL_HOME
"$HOME/Library/Application Support/AI-Protokolist/runtime/bin/python" -m unittest discover -s tests -v
node --check app/static/app.js
```

Для пользовательского сценария загрузите две предоставленные организаторами записи по очереди, проверьте русские/казахские/смешанные реплики, сравните извлечённые поручения с эталонными DOCX, исправьте расхождения, утвердите и откройте PDF/DOCX. Затем сделайте короткую запись микрофона. Для Meet, Zoom и Teams нужны три отдельные тестовые ссылки и организатор, который допустит участника; без этого нельзя честно заявить, что фактическое подключение к каждой платформе проверено.

Распознавание RU/KK/смешанной речи поддерживается многоязычной моделью, но его точность на конкретной акустике **не гарантирована**. Диаризация по голосу даёт метки, а не имена; имена подтверждаются секретарём. Нужны отдельные контрольные записи и метрики WER/DER и точности поручений для заявлений об «идеальном» качестве.

## Ограничения и безопасность

- Исходный звук не отправляется в OpenAI, NVIDIA или другой облачный AI. Бюджет API для локального сценария не нужен. Открытие реальной ссылки Meet/Zoom/Teams, естественно, использует сеть самой платформы видеосвязи.
- Прототип хранит файлы и SQLite без шифрования, ролевого доступа и политики удаления. Перед использованием в защищённом контуре нужны аутентификация/SSO, шифрование на диске, секреты, резервное копирование, аудит доступа, retention, контроль согласия, изоляция сети и согласование с ИБ заказчика.
- Автоматическая рассылка напоминаний, СЭД и полностью автономный bot join **не реализованы**. Дашборд подсвечивает ближайшие и просроченные сроки, но не отправляет уведомления.
- При отказе модели ошибка видна в карточке; результат не маскируется фиктивным протоколом. Есть ручной повтор обработки.
- `PROTOCOL_OLLAMA_URL` по умолчанию `http://127.0.0.1:11434/api/chat`, `PROTOCOL_OLLAMA_MODEL` — `qwen3:4b`, `PROTOCOL_PDF_FONT` позволяет указать Unicode TTF.
