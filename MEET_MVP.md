# Google Meet MVP на macOS

Бот открывает встречу в отдельном постоянном профиле Chrome, входит с Google-аккаунтом как видимый участник, записывает входящий звук и создаёт расшифровку и протокол. Камера и микрофон бота выключены. WhatsApp не используется.

## Первый запуск

1. Установите Google Chrome и инструменты командной строки Xcode (`xcode-select --install`, если `swiftc` отсутствует).
2. В папке проекта установите зависимости:

   ```bash
   .venv/bin/pip install -r requirements-client.txt -r requirements-openai.txt
   ```

3. Дважды нажмите `start_meet_login.command`. В открывшемся **отдельном** Chrome вручную войдите в Google-аккаунт бота. Пароль, второй фактор и CAPTCHA вводятся только человеком в Google. После входа завершите этот Chrome через меню «Chrome → Выйти из Google Chrome».
4. Авторизация сохраняется в `.meet-bot-profile/`. При следующих запусках пароль обычно не нужен; если Google завершит сессию, повторите шаг 3. Одновременно использовать этот профиль в двух запусках нельзя.
5. При первом захвате разрешите запись экрана и системного аудио приложению запуска в «Системные настройки → Конфиденциальность и безопасность». Для запуска через `.command` это обычно Terminal. После изменения разрешения может потребоваться перезапуск приложения запуска.

Имя видимого участника берётся из Google-аккаунта. Для постоянной работы используйте отдельный аккаунт с понятным именем, например «AI Протоколист». Гостевое поле имени не используется. Организатор и участники должны знать о записи.

## Обычный запуск

Сохранённая тестовая ссылка находится в `.meet-meeting-url`. Файл содержит только URL вида `https://meet.google.com/abc-defg-hij`.

Дважды нажмите `start_meet_bot.command`. Если ключа нет в переменной окружения `OPENAI_API_KEY`, Terminal запросит его скрытым вводом. Ключ не записывается в проект и не нужен в чате.

Для другой встречи:

```bash
./start_meet_bot.command --meeting-url https://meet.google.com/abc-defg-hij
```

Бот использует сохранённый аккаунт и нажимает кнопку входа. Если требуется допуск, организатор принимает его обычным способом. При отказе или проверке Google бот останавливается. Повторных запросов и обхода ограничений нет.

Дождитесь сообщения `Recording started`. Говорящий должен находиться **на другом устройстве или в другом клиенте встречи**: микрофон бота не записывается. Если аккаунт уже участвует на другом устройстве, бот выбирает «Подключиться также на этом устройстве», сохраняя исходное подключение. Companion не используется.

После отключения бота или завершения встречи в интерфейсе Meet запись закрывается и начинается обработка. Для завершения вручную нажмите **Ctrl-C один раз** в Terminal. Не закрывайте Terminal до появления пути к DOCX. Если бот уже видел других участников и остался один, он выходит через 60 секунд. Это можно отключить параметром `--alone-timeout-seconds 0`. Если счётчик участников недоступен из-за изменения интерфейса Meet, используйте Ctrl-C.

Все результаты лежат в `data/meet_<дата>_<время>/`:

- `speaker_mixed.wav` — исходная запись, 16 кГц, моно, PCM16;
- `audio_stats.json` — длительность и уровень звука;
- `transcript.json` и `transcript.txt` — реплики с временными метками и голосами;
- `protocol.json` и `protocol.docx` — итоги, решения и поручения на русском и казахском, затем исходная расшифровка;
- `processing.json` — состояние обработки и тип ошибки, если она возникла.

Без явно названного исполнителя или срока записывается `null`; такое поручение помечается для уточнения. Метки `partN_…` действуют только внутри фрагмента и не определяют личность. Относительные сроки сохраняются как произнесены. Протокол следует проверить перед использованием.

В JSON прежние поля `summary`, `decisions`, `tasks[].action` и `tasks[].deadline` содержат русский вариант. Поля с суффиксом `_kk` содержат казахский перевод; элементы `decisions` и `decisions_kk` соответствуют друг другу по порядку. `assignee` сохраняет имя без перевода, а `evidence` — дословную реплику на языке записи. Если срок не установлен, `deadline` и `deadline_kk` равны `null`. Старые JSON без полей `_kk` можно по-прежнему вывести в одноязычный DOCX, но новая обработка создаёт двуязычный протокол.

## Повторная обработка без новой встречи

При ошибке API исходный WAV сохраняется. Дважды нажмите `process_meet_recording.command`, введите имя папки сессии и ключ скрытым вводом. Или:

```bash
./process_meet_recording.command --session meet_20260923_120000
```

Если расшифровка уже сохранена для этого аудио и модели, она используется повторно. При ошибке посреди распознавания длинной записи распознавание фрагментов начнётся заново. Тишина не отправляется в API.

## Проверки отдельных этапов

Вход без записи и без ключа:

```bash
./start_meet_join.command
```

Вход и запись на 60 секунд без отправки в API:

```bash
.venv/bin/python -u -m meeting_bot.meet_client --record-only --max-duration-seconds 60
```

Сохранённые записи никогда не перезаписываются новым запуском с тем же `--session`.

Захват отдельного Chrome без встречи:

```bash
.venv/bin/python -m meeting_bot.capture --capture-mode mac --record-only --session audio_check --duration-seconds 10
```

Если запущено несколько процессов Chrome, укажите `--chrome-pid`. Их идентификаторы показывает `.build/mac_audio_capture --list-apps`. В обычном запуске бот передаёт свой идентификатор автоматически. На этом Mac включение только процесса Chrome в фильтр ScreenCaptureKit давало тишину из-за его дочерних аудиопроцессов. Рабочий режим исключает остальные видимые системе приложения и обновляет список каждые 5 секунд. Это не строгая изоляция одной вкладки: звуки новых или не перечисленных системой процессов могут попасть в запись. Во время встречи выключите другие источники звука на Mac; вкладки самого Chrome тоже могут записываться.

## Модели и ограничения

По умолчанию используются `gpt-4o-transcribe-diarize` и `gpt-4.1-mini`. Их можно заменить параметрами `--transcribe-model` и `--summary-model`. Требования диаризации: [официальная документация OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text). Аудио разбивается на фрагменты по 8 минут; для diarize передаётся `chunking_strategy="auto"`.

Запись и расшифровка передаются в OpenAI. Профиль, ссылки и результаты исключены из Git. Максимальный размер текста для суммаризации MVP — 120 000 символов; при превышении расшифровка остаётся на диске. При необходимости локальной обработки сохранён прежний `--provider local` с `--whisper-model` и `--ollama-model`; нужен заранее установленный Ollama и модели.

## Фактическая проверка 23 сентября 2026

Подтверждены ручная первичная авторизация, повторный автоматический вход в настоящую встречу из постоянного профиля и запись 75,26 секунды входящего звука. Результат: `data/meet_live_20260923_b/speaker_mixed.wav`, peak 8988, RMS 231,98. Контрольный тон Chrome 440 Гц также записан и подтверждён анализом частоты. Для теста пользователь выбрал свой Google-аккаунт; отдельный рабочий аккаунт бота ещё нужно завести/выбрать. OpenAI на этой записи не вызывался: ключ отсутствовал в окружении, а затем пользователь передал ИИ-обработку другому участнику команды. DOCX проверен на тестовых данных, не на расшифровке этой встречи. Автоматический выход по счётчику участников реализован, но уход последнего человека в живом тесте не проверялся.
